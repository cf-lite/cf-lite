# Conventions: how a file layout becomes generated code

cf-lite has no runtime. Everything a convention does happens at build time: `generate()` (called by the Vite plugin on start and on every route-file change)
writes real `.ts` files under `.cf-lite/` that your Worker imports. Conventions are *contributors* (`packages/cf-lite/src/conventions/`); `generate.ts`
only knows the shape of the output files, never a particular convention. **A new convention is a new file, not an edit of `generate.ts`.**

| Built-in | Scans | Contributes |
|---|---|---|
| `api` (`conventions/api.ts`) | `server/api/**` | `.route("/x", aN)` on the `api` Hono |
| `pages` (`conventions/pages.ts`) | `app/routes/**` | SSR `.get(...)` handlers in `app.ts`; the client table `routes.ts` |
| `typegen` (`conventions/typegen.ts`) | (reads `pages` + `routes`) | `.cf-lite/typed-routes.d.ts`: typed `href()` / `<Link to>` / `PageProps` (see [typegen.md](typegen.md)) |
| `routes` (`conventions/routes.ts`) | `server/routes/**` | non-API Hono handlers at their own URL + Worker-first globs (see [routing.md](routing.md)) |

## The contract

```ts
import { defineConvention } from "cf-lite/conventions";

export default defineConvention<string[]>({
  name: "queues",                              // unique; key of ctx.entries
  scan: ({ root, adapter }) => [...],          // read the project, return entries
  emit: (entries, ctx) => ({                   // ctx.entries = what every convention scanned
    imports: [`import q0 from "../server/queues/jobs";`],
    handlers: { imports: [...], queue: "(b, e, c) => q0(b, e, c)" },
    workerFirst: [],
    checks: [(wrangler) => wrangler.queues ? [] : ["server/queues/jobs.ts exists but wrangler has no `queues` config"]],
  }),
});
```

Built-ins live in `conventions/index.ts` (`builtinConventions`, emit order). Project-local ones: `cfLite({ conventions: [queues] })` in `vite.config.ts` (run after the built-ins).

### Slots of `.cf-lite/app.ts`

```ts
// generated by cf-lite — do not edit
import { Hono } from "hono";
<preImports> <imports>
<declarations>
export const api = new Hono<{ Bindings: Env }>()  <api>  ;
export type ApiType = typeof api;
export const app = new Hono<{ Bindings: Env }>()  <appPre>  .route("/api", api)  <app>  ;
<exports>
export default app;
```

`appPre` is where middleware (`.use(...)`) goes so it runs before `/api`; `app` takes any Hono chain method (`.get`, `.onError`, ...).
Other `Emission` fields:

- `files` — extra generated files under `.cf-lite/` (clashes between conventions are an error).
- `handlers` — see below.
- `workerFirst` — extra `assets.run_worker_first` globs; merged (deduplicated, sorted) with the SSR route globs. Static paths still never invoke the Worker.
- `checks` — functions of the parsed `wrangler.jsonc`/`.json` returning warnings; printed by the Vite plugin (`[cf-lite] ...`) at startup. Not run when the file can't be parsed.

### `.cf-lite/handlers.ts` (queue / scheduled / email / tail / trace)

Written only when a contributor provides a non-fetch handler (otherwise the file does not exist; a stale one is deleted). Two contributors providing the same
handler is an error (compose them inside one). Wire it in `server/worker.ts`:

```ts
import app from "../.cf-lite/app";
import { handlers } from "../.cf-lite/handlers"; // only once a convention generates it
export default { fetch: app.fetch, ...handlers } satisfies ExportedHandler<Env>;
```

## `Env`: the augmentation point

Generated code types bindings with the **global** `Env` interface (`Hono<{ Bindings: Env }>`). Declare your bindings once, in a file tsc includes
(`server/env.d.ts` in the scaffolds), or let `wrangler types` generate `worker-configuration.d.ts`:

```ts
// server/env.d.ts
interface Env { DB: D1Database; MY_QUEUE: Queue<{ id: string }> }
```

Modules and conventions that need bindings extend the same global with declaration merging from their own `.d.ts`
(`interface Env { CF_CACHE_TAGS?: KVNamespace }`), so nothing in `generate.ts` has to know about them.

## Package exports

`cf-lite/modules/*` is a wildcard export (a new `src/modules/foo.ts` is importable as `cf-lite/modules/foo` with no `package.json` edit); `cf-lite/conventions` and
`cf-lite/conventions/*` expose the contributor API.

## Stability tests

`packages/cf-lite/test/seams-golden.test.ts` pins the generated `app.ts` + `routes.ts` of all 7 examples byte-for-byte (goldens in `test/golden/`; refresh only on an
intentional output change with `UPDATE_GOLDEN=1`). `test/conventions.test.ts` adds a dummy convention through every slot with no `generate.ts` edit.
