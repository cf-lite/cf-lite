# Accessibility

What cf-lite does for you, what it tests, and what stays your job. This page only states what the code and tests do today.

## Built in

* **Client navigation**: after a route change the router updates a polite live region (`aria-live="polite"`, one reused element) (`#cf-lite-announcer`, text = `document.title`), moves focus to `<main>` (or `<h1>`, `tabindex=-1` added) and scrolls to the top or the `#hash` target ([routing.md](routing.md)).
* **No-JS first**: `static` and `ssr` pages are real HTML; forms post and redirect without JavaScript ([actions.md](actions.md)), so assistive tech never depends on hydration.
* **Fonts**: generated fallback faces avoid layout shift ([assets.md](assets.md)); `<Image>` always emits intrinsic `width`/`height` ([images.md](images.md)).
* **`<html lang>`** and `hreflang` from the i18n module ([i18n.md](i18n.md)).

## Tested

`@cf-lite/playwright` ships an `a11y()` fixture running axe-core (WCAG 2.0-2.2 A/AA) and failing on violations at or above `serious`; its own suite proves a seeded violation fails ([testing.md](testing.md)).
Browser suite (`e2e/`, `bun run test:browser`, chromium in CI):

* **Docs site** (`site/`): `e2e/docs-a11y.spec.ts` runs axe (WCAG 2.0-2.2 A/AA, fails on serious+) on every page linked from the home page, in light and dark colour schemes. It found one violation (dark-theme code blocks, `github-dark-dimmed` tokens under `color-contrast`), fixed by switching the dark Shiki theme to `github-dark-high-contrast`. It is one more Playwright project, so it runs with the rest of `test:browser` (and in CI).
* **Per adapter** (react, preact, vue, svelte, solid; the shared `e2e/site.spec.ts`): after a client navigation, by link click, by keyboard (focus + Enter) and by browser Back, the test asserts exactly one `#cf-lite-announcer` with `aria-live="polite"` and text = `document.title`, `document.activeElement` is `<main>`, scroll is back at 0, and the swapped view is axe clean. It found one gap: the announcer was `aria-live="assertive"` while the docs promised polite (a route change should not interrupt speech); now polite.
* **Engines**: `bun run test:browser:all` runs the whole suite in chromium, firefox and webkit (`PW_BROWSERS=chromium,firefox,webkit`; `bunx playwright install firefox webkit` once; webkit also needs the OS libraries from `sudo bunx playwright install-deps webkit`). CI stays chromium-only to save Actions minutes. Verified firefox 155: 65/65 (2026-10-02, a maintainer machine). WebKit is wired but has **not** been run: that machine lacks `libgtk-4`/`libwebkitgtk-6.0` and no root access was available.

Manual screen-reader pass (OBSERVED-BY-HUMAN, 2026-10-06, no recording, so not VERIFIED): owner reported the pass as OK; no per-step notes; reader and browser not recorded; repeat with notes before 1.0. Script: [a11y-screen-reader-test.md](a11y-screen-reader-test.md), run against `examples/a11y-demo`.

Still manual: a keyboard pass on real assistive tech, and a different-engine run of the announcer (live-region behaviour differs per browser/SR pair).

## Your responsibility

Semantic markup, labels, colour contrast, alt text, keyboard paths in your own components. Add one `a11y()` assertion per page template to your Playwright suite:

```ts
test("home is accessible", async ({ page, a11y }) => { await page.goto("/"); await a11y(); });
```

Automated axe checks do not replace manual review; keyboard and screen-reader passes remain manual.
