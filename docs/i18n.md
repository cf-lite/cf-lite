# i18n

Path-prefix locales (`/en/...`, `/vi/...`) that stay Cloudflare-native: static pages are prerendered once per locale and served by the
assets layer, and **only `/` and unprefixed localized paths ever wake the Worker** (to redirect by language). Nothing here ships to the
Worker unless you use it. Example: `examples/site-i18n`; e2e: `scripts/i18n-e2e.mjs`.

## Setup

```ts
// vite.config.ts
cfLite({ renderer: react(), i18n: { locales: ["en", "vi"], default: "en", countries: { VN: "vi" } } })
```

| option | meaning |
|---|---|
| `locales` | tags as they appear in URLs (`en`, `pt-BR`). Validated at build. |
| `default` | served when nothing matches; catalog fallback; the `x-default` alternate. |
| `cookie` | cookie remembering an explicit choice (default `locale`). |
| `countries` | optional `request.cf.country` -> locale, consulted when `Accept-Language` matches nothing. |
| `langTags` | `<html lang>`/hreflang value when it differs from the URL tag (`{ vi: "vi-VN" }`). |

Pages live under `app/routes/[locale]/...` (the dynamic segment **must** be named `locale`). The plugin writes `.cf-lite/i18n.ts`
(`export const i18n`, `type Locale`, `localizedRoutes`) for pages/layouts to import.

```tsx
// app/routes/[locale]/_layout.tsx - <html lang> + hreflang for every page below
export const head = i18nHead(i18n);

// app/routes/[locale]/about.tsx
export const render = "static";
export const paths = () => localeParams(i18n);            // one prerendered page per locale (extra params: localeParams(i18n, [{ slug }]))
export const loader = async (c) => ({ messages: await load(c.req.param("locale")) });
export default ({ params, data }) => { const { t } = translator(data.messages, params.locale); return <h1>{t("about.title")}</h1>; };
```

A static `[locale]` page without `paths()` is a build error (there would be nothing to serve).

## Detection (only on `/` and unprefixed paths)

The generated Worker-first set contains exactly: `/`, the unprefixed form of each localized page (`/about`, `/posts/*`), and - for SSR
pages - one narrow glob per locale (`/en/posts/*`, `/vi/posts/*`; **not** `/*`). Prefixed static pages (`/vi/about/`) are plain assets:
no Worker invocation, no cost.

For those requests the `i18nMiddleware` answers `307` to `/<locale><path>` (query kept, `Vary: Accept-Language, Cookie`,
`Cache-Control: no-store`) with this precedence: **cookie > `Accept-Language` > `cf.country` > default**. `Accept-Language` matching is q-ordered,
exact tag first, then primary language (`vi-VN` -> `vi`, `pt-PT` -> `pt-BR`). Only GET/HEAD redirect.
A prefix that is not a locale on a localized route (`/xx/posts/a`) is a 404, never rendered with `locale = "xx"`.
Worker-served prefixed HTML gets `Content-Language`.

Remember a choice from a switcher with `localeCookie(i18n, "vi")` (`document.cookie = ...` on the client, or as a `Set-Cookie` value);
`localizePath(pathname, "vi", i18n)` builds the switcher href from the current path.

## Catalogs

Plain JSON per locale (split per namespace if you like). Each is one dynamic import, so each locale/namespace is its own chunk and a route only
bundles what it imports (per-route tree shaking by construction):

```ts
const catalogs = { en: () => import("./messages/en.json"), vi: () => import("./messages/vi.json") };
export const load = (locale: string) => loadMessages(i18n, catalogs, locale);   // default locale merged underneath = fallback
```

`translator(messages, locale)` gives `t(key, vars)` (dotted keys, `{name}` interpolation, plural objects `{ one, other, ... }` chosen by
`vars.count` via `Intl.PluralRules`), `has`, `number`, `date`. A missing key returns the key (hook: `onMissing`). Not an ICU MessageFormat
implementation; if you need full ICU, use your own library inside `loader`.

## hreflang, `lang`, sitemap

* `i18nHead(i18n)` (layout `head`) sets `<html lang>` and `<link rel="alternate" hreflang>` for every locale + `x-default`, from `params.locale`
  and the request path. It works prerendered, SSR and on SPA navigation (two small core additions: `Head.htmlAttrs` and `HeadCtx.url`).
  Absolute URLs need `SITE_URL` (same as `seo()`).
* Static sitemap (`SITE_URL` at build): `/<locale>/x` entries get `xhtml:link` alternates + `x-default` automatically.
* Dynamic `server/sitemap.ts`: `localizedEntries(["/", "/about", { url: "/p", lastmod }], i18n)` expands every path per locale with alternates.

## Not in 1.0

Domain-based locales (`example.fr`) need zone routes, so they are out of scope. `request.cf.country` is only present on Cloudflare (and
reflects your IP in `wrangler dev`). The locale is part of the URL, so a per-user cookie never changes a cacheable page.
